## 1. Objective

The objective of this report is to measure the extent to which the automated backend and frontend tests execute the application code. It identifies tested and less-tested areas to guide future testing.

## 2. Coverage Tools and Commands

| Component | Coverage tool | Command |
|---|---|---|
| Backend | Node.js built-in test coverage | `npm --prefix backend test -- --experimental-test-coverage` |
| Frontend | Vitest V8 coverage provider | `npm --prefix client test -- --coverage` |

The backend coverage was generated using Node.js built-in coverage support. Frontend coverage was generated using `@vitest/coverage-v8` version 2.1.9.

## 3. Backend Coverage Results

| Metric | Coverage |
|---|---:|
| Line coverage | 91.99% |
| Branch coverage | 82.82% |
| Function coverage | 92.35% |

### Backend observations

- Authentication middleware, account lockout, audit-log models and booking-related models achieved strong coverage.
- Several backend modules have lower coverage and need additional tests.
- The TLS module has lower line coverage because some server-related paths were not exercised in the available environment.
- Notification routes and some payment, authentication and audit-log paths have uncovered code.

## 5. Coverage Summary

| Metric | Backend | Frontend |

Backend and frontend percentages are reported separately because they were generated by different coverage tools and measurement outputs.

## 6. Analysis

- Backend line coverage is higher than frontend line coverage.
- Backend function coverage is 92.35%, indicating that most measured backend functions were exercised.
- Frontend branch coverage is 70.16%, showing that additional tests are needed for conditional UI and API behaviour.
- High line coverage does not necessarily mean that all decision paths or business scenarios have been tested.
- Uncovered code should be reviewed to determine whether it represents missing tests, unused code or environment-dependent functionality.

## 7. Recommendations

1. Add tests for uncovered branches in booking, payment and event API modules.
2. Improve tests for registration and other partially covered frontend components.
3. Add tests for notification route error and response paths.
4. Exercise TLS server paths in an environment where OpenSSL is available.
5. Review uncovered entry-point code and decide whether direct tests are appropriate.
6. Re-run coverage after additional tests are added and compare the results.

## 8. Conclusion

The backend achieved 91.99% line coverage, 82.82% branch coverage and 92.35% function coverage. The frontend achieved 86.01% statement and line coverage, 70.16% branch coverage and 78.26% function coverage.

The results indicate good execution coverage across the tested application, while also identifying areas where additional tests can improve confidence in the system.
